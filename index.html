The setting

What is a metadata cache?

  • A block cache keeps hot pages in DRAM to avoid SSD/HDD I/O.
  • Data cache holds the payload; the metadata cache holds the index that locates data — e.g. B-trees that map logical → physical block addresses.
  • It sits on the hottest path — consulted for almost every data access → extreme frequency, high concurrency, hit ratios near 100%.
Judged not only on miss ratio, but on CPU overhead, scalability, and simplicity.
Problem
Why metadata is different

Structural locality: a page packs many keys

  • A metadata page isn't one key — a B-tree leaf packs hundreds of mapping tuples.
  • L1 and L5 both live in leaf m4 → two lookups hit m4 twice.
  • Different accesses repeatedly hit the same page — by structure, not popularity.
  • Internal nodes m1–m3 are hit by every lookup → effectively pinned; we focus on leaves.
Problem
The problem

What is a correlated reference?

Because a page packs many keys, one operation touches many of them on the same page — so the page is hit many times at once, then goes cold.
The trap: counting each burst hit as a vote for hotness. A burst is one operation, not a hot block.
Problem
Why existing policies fall short

Filter too loosely, or too aggressively

S3-FIFO — over-promotes

A Ref bit is set on any re-hit in the Small FIFO. A correlated burst near the head sets Ref = 1 → the cold page is promoted to Main and pollutes the cache.

C burst hit → Ref=1 → wrongly promoted

Clock2Q / 2Q — under-promotes

A genuinely hot block reaches Main only after being evicted to Ghost and re-referenced — an extra, avoidable miss for every hot block.

H must miss once before it can be promoted
We want the direct-promotion speed of S3-FIFO without admitting correlated bursts.
Problem
Key insight

Where a re-hit happens tells you what it means

Add a Correlation Window at the head of the Small FIFO:
hits inside the window do not set the Ref bit.

Inside the window (just inserted)

A re-hit is almost certainly the same correlated burst → ignore it. Ref stays 0 → the page ages out to Ghost.

Beyond the window

A re-hit is genuine reuse → set Ref = 1 → promote directly to Main Clock, no extra miss.

A one-line change to S3-FIFO — no new tuning knobs, no ordered LRU.
Insight
Clock2Q+ design

Three queues + a correlation window

  • Cold / correlated → age out to Ghost (Ref = 0).
  • Hot (Ref = 1 at tail) → promoted directly to Main.
  • Ghost hit → proven reuse → admit to Main.
  • Main Clock → Ref gives a second chance before eviction.

Sizes: Small FIFO 10% (window = half), Main Clock 90%, Ghost 50%.

Design
Evaluating a metadata policy

Turning public block traces into metadata traces

  • No public metadata-cache traces exist; production traces can't be shared.
  • Idea: divide each block number by the B-tree fan-out (200) → the sequence of leaf-page accesses.
  • Reproducible from any public block trace.
Validated against a real B-tree leaf trace: < 0.01% miss-ratio difference.

Results
Engineered for production

Simplicity as a first-class requirement

Low overhead

Allocation-free, array-based queues. Hit path = one hash lookup + at most a Ref-bit set.

Scalable

Atomic head/tail indices & clock hand; fine-grained per-entry / per-bucket locks — no global lock.

Dirty-aware

Eviction & promotion skip dirty pages until flushed. Simulated miss-ratio impact: negligible.

Bounded work

Per-eviction scan is capped (skip < 2 on average) → no CPU spikes, no infinite loops.

Online resizing

Grow/shrink queues live, without rebuilding — required in a running system.

Deployment
Takeaways

Clock2Q+

  • Correlated references are a real, performance-critical metadata pattern that defeats one-hit-wonder filters.
  • The correlation window is a one-line change: filter bursts, still promote genuinely hot blocks directly.
  • Best miss ratio among SOTA on metadata and data — and it is deployed in VMware vSAN.
  • Low overhead, scalable, dirty-aware, resizable — simplicity pays off in production.
Reproducible: Clock2Q+ & the metadata-trace method are upstreamed in libCacheSim.
